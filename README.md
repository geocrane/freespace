# FreeSpace

Анализатор дискового пространства для АРМ и DataLab.
Показывает, чем занято место, находит большие файлы и одноимённые папки
(например, все `venv` разом) и убирает найденное в корзину — с возможностью
вернуть.

Основной интерфейс — веб: он одинаково работает на АРМ и в
DataLab контейнере с Jupyter.

## Быстрый старт

Скрипты сами создадут виртуальное окружение,
поставят зависимости при первом запуске, подберут свободный порт и откроют
браузер. Нужен только Python 3.10+.

| Где | Что сделать |
|---|---|
| **Windows** | двойной клик по `start.bat` |
| **DataLab** | открыть `start.ipynb`, вписать токен SberOSC в «Шаг 1», выполнить «Шаг 2» |

В тетрадке только две строки — `start(TOKEN)` и `stop()`; всё, что за ними стоит
(установка зависимостей из индекса портала, подбор порта, адрес за
`jupyter-server-proxy`), живёт в `freespace/notebook.py`.

## Запуск через консоль

```sh
python -m freespace.web
```

Команда печатает адрес — откройте его в браузере.


### Переменные окружения

| Переменная | Что делает |
|---|---|
| `FREESPACE_CACHE_DIR` | каталог для снимков вместо системного по умолчанию |
| `FREESPACE_CONFIG` | файл со списком сетевых папок вместо `config.json` рядом с кэшем |
| `FREESPACE_ENV` | файл `.env` не рядом с приложением, а по указанному пути |
| `FREESPACE_PIN` | PIN на сетевые папки; перекрывает значение из `.env` |
| `FREESPACE_ROOTS` | список предлагаемых корней через `:` вместо автоопределения |
| `FREESPACE_ROOT_PATH` | префикс URL |

Первым в списке корней всегда идёт домашний каталог: документы, загрузки и
рабочие файлы, и разбирать место почти всегда нужно именно там — на диске
целиком половина принадлежит системе и всё равно не удаляется.

В Linux-контейнере корнем является `/nfs`:

## Как работать

### 1. Просканировать

В поле сверху — путь к папке или диску; под ним кнопками перечислены тома и
домашний каталог со свободным местом. Нажмите **«Сканировать»**.

- Идёт обход `os.scandir` очередью каталогов: узкое место здесь
  — задержка ввода-вывода, а не процессор, и на сетевых дисках выигрыш даёт
  именно большое число одновременных запросов.
- Виден прогресс. **«Отмена»** прерывает обход, но не выбрасывает результат —
  на экране останется то, что успели собрать.
- Если этот корень уже разбирали в последние сутки, результат покажется
  мгновенно из сохранённого снимка, с пометкой возраста данных.
  **«Пересканировать всё»** обходит заново, не доверяя снимку.


### 2. Смотреть карту и содержимое

Слева — **treemap**, плитки, пропорциональные размеру.

- Клик по папке — открыть её.
- Клик по файлу — подсветить его строку в списке справа и прокрутить к ней.
- Плитка «остальное» собирает мелочь сверх лимита: она ничего не изображает и
  никуда не ведёт.

Справа вкладка **«Содержимое»**: состав текущей папки с размерами и долей от
родителя.

### 3. Искать

Вкладка **«Поиск»** ищет по уже просканированному дереву — мгновенно, без
повторного обхода.

| Поле | Смысл |
|---|---|
| строка запроса | имя целиком, часть имени или шаблон вида `*.iso` |
| режим | «часть имени» / «по шаблону с `*`» (понимает `*` и `?`) / «имя целиком» |
| тип | и папки, и файлы / только папки / только файлы |
| вид файлов | видео, аудио, изображения, архивы, образы дисков, документы, код, установщики, базы данных, прочее |
| «больше, МБ» | нижняя граница размера |
| «не трогали с» | показать только то, чего с этой даты не касались. Для папки это значит «ни один файл внутри не менялся и не появлялся с тех пор»: одного свежего файла хватает, чтобы папка в список не попала |
| **скрывать вложенные результаты** | убирает находки, лежащие внутри других находок: если папка попала в результат целиком, её подпапки попали автоматически, а удалять надо внешнюю |
| **объединять одинаковые имена** | сводит одноимённые находки в одну строку — «сколько у меня всего `venv` и сколько они занимают» одним ответом; строка разворачивается в список самих папок |
| **искать только в открытой папке** | сужает поиск до текущего поддерева |

### 4. Готовые наборы условий

Шаблоны под полем поиска заполняют фильтры и сразу ищут:

| Набор | Что находит |
|---|---|
| файлы больше 100 МБ | все крупные файлы |
| видео | по расширению |
| архивы | по расширению |
| `__pycache__` | папки байткода, с группировкой |
| автосохранения Jupyter | `.ipynb_checkpoints` |
| виртуальные окружения | шаблон `*venv` — ловит и `venv`, и `.venv` |
| не трогали больше года | папки, где за год не менялся и не появлялся ни один файл — кандидаты на разбор. Только самые верхние: если папка залежалась целиком, то и всё внутри неё тоже, а разбирают внешнюю |


### 5. Отметить и удалить пачкой

Панель над
списком показывает, сколько объектов отмечено и сколько они занимают;
**«выбрать все»** отмечает весь список, **«Удалить отмеченные»** уносит всё в
корзину. 


### 6. Корзина

Удалённое переезжает в `~/.freespace-trash`

На вкладке **«Корзина»** видно, что удалено, откуда и сколько занимает. Рядом с
каждой записью — **«Восстановить»**: исходный путь лежит в `meta.json`, объект
вернётся на место. Кнопка **«Очистить корзину»** удаляет файлы полностью.

Место освобождается только после очистки, поэтому сама корзина остаётся в
списках отдельной строкой с размером.


### Частые задачи

| Задача | Как |
|---|---|
| «Куда делось место на диске» | «Сканировать» домашний каталог → смотреть карту, проваливаться в крупные плитки |
| «Сколько весят все мои venv» | «Поиск» → набор «виртуальные окружения» → включить «объединять одинаковые имена» |
| «Убрать весь питоновский мусор» | наборы `__pycache__` и «автосохранения Jupyter» → «выбрать все» → «Удалить отмеченные» |
| «Найти старые образы дисков» | «Поиск» → вид файлов «образы дисков» → «больше, МБ» = 500 |
| «Что тут залежалось» | «Поиск» → набор «не трогали больше года» → смотреть колонку «Трогали» |
| «Разобрать одну папку» | открыть её на карте → галочка «искать только в открытой папке» |
| «Вернуть удалённое» | вкладка «Корзина» → «Восстановить» |
| «Освободить место окончательно» | вкладка «Корзина» → «Очистить корзину» |

## Сетевые папки

Общие диски разбираются так же, как локальные, но заперты PIN-кодом: пока он не
введён, сетевых дисков в списке томов нет вовсе — ни подключённых букв вроде
`Z:`, ни вписанных руками шар.

### Что этот PIN делает и чего не делает

Он закрывает **кнопки в этом приложении**, а не файлы на шаре. У кого есть
доступ к сетевой папке, тот удалит оттуда что угодно Проводником, не открывая
FreeSpace, а сам файл настроек лежит на той же машине. Смысл в другом: общий
диск не мозолит глаза, случайно очистить его в один клик нельзя, и тот, кто
разбирает место, делает это осознанно. **Настоящее разграничение доступа — это
права на самой шаре**, и подменить их PIN-код не может.

### Как настроить

Ничего в консоли делать не нужно.

1. Запустить приложение, нажать в шапке **«🔒 сетевые диски»** и ввести PIN.
   По умолчанию он **`admin`**.

2. Кнопкой **«⚙ список сетевых папок»** добавить путь целиком — `\\сервер\общая`
   или `Z:\Отдел`. Список ведётся руками: сеть приложение не обшаривает.

Сменить комбинацию — в файле `.env` рядом с `start.bat`. Он создаётся сам при
первом запуске, правится блокнотом, и в нём одна значащая строка:

```ini
FREESPACE_PIN=admin
```

После правки приложение нужно перезапустить. Если стереть значение совсем
(`FREESPACE_PIN=`), сетевые папки не откроются вообще ничем.

PIN лежит там открытым текстом, и это осознанно: замок закрывает кнопки в
приложении, а не файлы на шаре, так что прятать комбинацию не от кого — а вот
менять её человек должен уметь блокнотом, не запуская ничего в консоли.

Дальше сетевые папки работают как обычные — с двумя отличиями. Они помечены 🌐 и
рыжим цветом, а пока открыт общий диск, над окном висит полоса с
предупреждением: удалённое пропадёт у всех, кто к нему подключён. Корзина
создаётся на самой шаре (`\\сервер\общая\.freespace-trash`), поэтому вернуть
удалённое можно, пока её не очистили.

Разблокировка живёт до конца работы приложения: закрыли окно или перезапустили
сервер — снова нужен PIN.

## Что считается «не трогали»

Отбор по дате опирается не на время изменения файла, а на **время последней
активности** — самое свежее из двух:

| Штамп | Что означает |
|---|---|
| время изменения (`mtime`) | когда последний раз меняли содержимое |
| время появления здесь | когда файл возник на этом диске: `st_ctime` на Windows — время создания, на Linux и NFS — время изменения inode |

Так сделано потому, что `mtime` переезжает вместе с файлом при копировании.
Файл, принесённый на новый компьютер в этом году с флешки, из архива или из
дистрибутива, честно показывает позапрошлый — содержимое с тех пор правда не
менялось. Если считать по одному `mtime`, поиск «не трогали больше года»
вываливает свежепринесённые данные. Время появления такого не умеет:
копирование, распаковка и загрузка по сети ставят его заново.

Стоит это ноль: оба штампа приходят одним и тем же вызовом `stat`, который
сканер и так делает.

У папки время активности — **самое свежее среди файлов внутри**, поэтому
«не трогали больше года» означает буквально «ни один файл здесь не менялся и не
появлялся». Одного свежего файла хватает, чтобы папка из списка исчезла.

Чего этот подход не покрывает — важно знать, потому что находки всё равно
придётся смотреть глазами:

- `robocopy /COPYALL` и восстановление из бэкапа переносят и время создания:
  такая папка будет выглядеть старой. Впрочем, залитый бэкапом и с тех пор не
  тронутый архив — это и есть кандидат на разбор.
- Массовая смена прав по всей шаре обновит время сразу всем файлам, и
  залежавшееся на время перестанет находиться. Ошибка идёт в безопасную сторону:
  не предложить нужное лучше, чем предложить удалить лишнее.
- Время последнего **чтения** не используется: на Windows его обновление по
  умолчанию отключено, а где включено — его протаптывают антивирус и служба
  индексации, и всё выглядит свежим.
- Где прочитать сведения о файле не удалось, в колонке «Трогали» стоит `—`, и в
  «залежавшееся» такой объект не попадает: предлагать удалить то, о чём ничего
  не известно, нельзя.

## Если что-то не работает

| Симптом | Что делать |
|---|---|
| «Не установлен uvicorn» | `pip install -r requirements.txt` |
| порт занят | `python -m freespace.web --port auto` |
| Windows не находит Python | Установить последнюю версию со SberOSC|
| в контейнере не ставятся зависимости | впишите токен SberOSC в ячейку «Шаг 1» |
| в контейнере пустая страница или 404 | в окружении нет `jupyter-server-proxy`; ячейка запуска 
| в контейнере сервер не поднялся | полный лог рядом с проектом: `.freespace-server.log` |
| не видно сетевых дисков | они скрыты до ввода PIN: кнопка «🔒 сетевые диски» в шапке, по умолчанию `admin` |
| PIN не подходит | значение берётся из `.env` рядом с `start.bat`; после правки файла приложение нужно перезапустить |
| «Это сетевая папка — общий диск» | разблокировка истекла или сервер перезапускали: нажмите «🔒 сетевые диски» и введите PIN заново |
| в «не трогали больше года» пусто, хотя данные старые | значит, файлы принесли на этот диск недавно — см. [Что считается «не трогали»](#что-считается-не-трогали) |
